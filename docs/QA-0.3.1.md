# 0.3.1 窗口拖动修复验证

日期：2026-10-15。基线 `832d7d4`；官方 DSH `0.2.0-rc.2 / macOS arm64`，隔离浏览器为 Chrome。

## 原因与改动

宿主样式 `html[data-platform=darwin] body>:not(#root){-webkit-app-region:no-drag}` 将插件的全屏弹窗挂载容器排除出原生窗口拖动区域，普通 `pointer-events:none` 不会取消该区域。修复后空容器为零宽高、子元素可溢出；菜单、通知和弹窗仅在显示区域声明 `no-drag`，遮罩从顶部 44px 以下开始。

## 验收清单

- 原生鼠标拖动：旧版复现，修复版空闲／菜单展开／设置打开／关闭／禁用／重启；记录窗口坐标。
- 页面区域：空闲容器零尺寸；菜单／通知／遮罩的实际边界和 app-region；透明标题区仍命中宿主。
- 交互回归：角色拖动及位置保存、气泡推进、菜单点击、设置输入／取消／关闭、禁用清理。
- 探索情况：窄窗口及窗口缩放后遮罩不盖住标题区；重复打开／关闭没有残留遮罩。
- 类型检查、既有测试、构建、包审计和 CI；原始设置验收后恢复。

## 结果

| 项目 | 结果与验证方式 |
| --- | --- |
| 原生窗口拖动 | 用户在本机安装、启用并重启 0.3.1 后用真实鼠标确认“已恢复，可以拖动” |
| 原生自动化限制 | 自动化鼠标在插件禁用时也不能稳定带动窗口，未能建立有效对照；该过程的坐标变化不作为拖动通过证据。菜单／设置打开时的原生窗口位移未单独人工验收 |
| 桌面挂载与遮罩 | 实际桌面读取旧容器为 1280×820 / no-drag，新容器为 0×0 / no-drag；设置遮罩 top=44，顶部命中宿主 drag 区域 |
| 隔离区域检查 | 使用宿主同款 body 子节点 no-drag 规则；空容器 0×0，标题栏命中保持；菜单 235px 宽、通知卡片 380px 宽均仅自身声明 no-drag；遮罩从 y=44 开始 |
| 角色与气泡 | 隔离鼠标拖动保存到 (792,492)，边缘锚点 right/bottom=(180,100)，刷新后位置一致；角色点击及气泡推进内容发生变化 |
| 设置与关闭 | 隔离输入刷新间隔 75 后取消，宿主仍为 60；三次打开／关闭无剩余遮罩；通知卡片关闭正常 |
| 窄窗口 | 隔离 560×760 下弹窗内容 clientWidth=scrollWidth=496，遮罩仍从 y=44 开始，标题栏命中正确；恢复 1280×900 后重复打开正常 |
| 禁用与重启 | 实际桌面禁用后挂件移除，body 仅余宿主 root；重新启用并重启正常，恢复验收前的全部插件设置与角色位置；用户随后确认原生拖动恢复 |
| 构建检查 | 类型检查、27 项既有 Node 测试、构建及 npm 包审计通过；CI 执行同一检查并生成安装包 |

本轮未增加宿主接口、设置字段或状态迁移。原生窗口拖动的人工反馈与浏览器 CSS／DOM 自动检查分别记录，不以浏览器检查冒充原生窗口验证。未主动发起付费模型调用，未修改凭据、气泡配置或用户素材，npm 不发布。Windows/Linux 未验证。
